# Тестовые талоны для мониторинга

20 талонов — **клон** реальных записей с **нескольких дат** (2026-05-04 … 2026-05-08 и базовые 2026-05-06), перенос на **сегодня по МСК** (`SYSDATETIME()`). Маршруты **1–3 этапа**.

**Маркер отката:** `id_client` 99990001…99990020 (не `DASHBOARD_TEST` в `info`).

**Статусы БД:** у талона `id_status_app` 5 — «На паузе»; «Ожидание результатов» только у этапа (`id_status_item` 5). Талоны 8, 20: статус талона **1**, текущий этап **5**.

**ФИО клиента:** `info = N'-'` — в конфигураторе без ФИО пациента.

## Правила логической корректности

- У врача **не более одного** пациента на приёме (`time_start_servicing`, без `time_end_servicing`).
- У врача **не может** быть одновременно пациент на приёме и вызванный пациент.
- На приёме + другие в очереди ожидания (без вызова) — **допустимо** (талоны 1, 2 у врача 53, талон 16 на приёме у другого врача).
- Времена этапов: `call >= start >= end` (минуты назад), следующий вызов не раньше окончания предыдущего этапа.
- Нет процедурного кабинета (`id_specialty` 25) на тестовых маршрутах.

## Разброс времён

**Максимум ожидания в листе и метриках — не более 20 мин.**

Прибытие: **12–24 мин** назад (разные значения по талонам).

Ожидаемо на `/dashboard` после reseed (только тестовые строки):

- лист ожидания: **~11–13** строк (wait + called + results)
- карточки: **~11** в очереди, **~6** на приёме (6 врачей с time_start_servicing), **~20** выдано (тест), **~3+** принято
- загрузка врачей: **~10–14** карточек с открытыми сменами
- метрики ожидания: max **≤ 20 мин**, несколько различных значений
- модалка «Потенциальные пациенты» (клик по строке «Состояние врачей»): талон, категория обслуживания, приоритет, время ожидания, вызов (Вызван / Не вызван); у талонов 1 и 2 один врач — **≥ 2** строк

`dashboard-test-verify-today.sql` проверяет: `category_name_check`, `call_variety_check`, `multi_patient_doctor_check`, `doctor_in_service_and_called_check`, `doctor_multi_in_service_check`, `timestamp_order_check` — все **OK**.

## Полная очистка дня

Удалить **все** талоны и смены за календарную дату (не только тестовые `id_client`):

```bat
sqlcmd -S localhost\SQLEXPRESS01 -d ElectronicQueueProf -E -i purge-date.sql
```

В [`purge-date.sql`](purge-date.sql) по умолчанию `@purgeDate = '2026-05-31'`. Для текущего дня замените на `CAST(SYSDATETIME() AS date)`.
