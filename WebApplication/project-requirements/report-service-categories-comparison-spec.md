# Отчёт «Сравнение категорий обслуживания» (`service-categories-comparison`): содержание и правила расчёта за период

Документ задаёт **единые определения и ожидаемое содержание** отчёта для приёмки и интерпретации результатов. Идентификатор в каталоге — `service-categories-comparison` (см. `appsettings.json` → `Reports.Catalog`). Реализация: `ServiceCategoriesComparisonReportGenerator`, сборка таблицы — `ServiceCategoriesComparisonReportBuilder`.

---

## 1. Назначение

Отчёт отвечает на вопросы:

- Сколько **приёмов** по каждой **категории** обслуживания попало в период?
- Каковы **среднее, минимум и максимум** ожидания до вызова и длительности приёма (мин) по этапам в разрезе категории?
- Какова **доля одно- и многоэтапных маршрутов** за период (только на диаграмме)?

Усреднение, минимум и максимум ожидания и длительности — по **строкам `List_item`** с валидными интервалами (см. §4.2–4.6); это не обязательно «одно значение на приём».

---

## 2. Объект анализа и разрезы

- **Строка отчёта** — одна **категория**: пара (`Appointment.id_category`, `Category.name`).
- Фильтра по категории в параметрах отчёта **нет** — всегда все категории периода.
- Порядок строк: по **`Category.name`** по возрастанию.

---

## 3. Источники данных (внешняя БД электронной очереди)

| Сущность | Таблица | Назначение в отчёте |
|----------|---------|----------------------|
| Этап | `List_item` | Времена вызова и обслуживания; подсчёт C этапов на приём. |
| Приём | `Appointment` | `date_arrival`, `id_category`, `time_arrival`. |
| Категория | `Category` | Наименование для строки отчёта. |

---

## 4. Определения

### 4.1. Число приёмов в строке

Число **уникальных** `id_appointment` среди всех строк выборки (`List_item` + приём), отнесённых к данной категории.

### 4.2. Ожидание до вызова для одной строки `List_item`

При заданном **`time_call`**:

\[
\text{Combine}(\text{date\_arrival}, \text{time\_call}) - \text{Combine}(\text{date\_arrival}, \text{time\_arrival})
\]

в минутах. Учитывается только если **0 ≤ значение < 10080**.

### 4.3. Среднее ожидание до вызова по категории

Среднее арифметическое по всем минутам из §4.2 внутри категории. Если множество пусто — **«—»**; иначе округление до **одного** десятичного знака (`CatalogReportShared.F1`).

### 4.4. Минимум и максимум ожидания до вызова по категории

Минимум и максимум по множеству минут из §4.2; при пустом множестве — **«—»**; иначе округление как в §4.3.

### 4.5. Длительность приёма для одной строки `List_item`

При заданных **`time_start_servicing`** и **`time_end_servicing`**:

\[
\text{Combine}(\text{date\_arrival}, \text{time\_end\_servicing}) - \text{Combine}(\text{date\_arrival}, \text{time\_start\_servicing})
\]

в минутах, с тем же фильтром **0 ≤ значение < 10080**.

### 4.6. Средняя, минимальная и максимальная длительность приёма по категории

По множеству минут из §4.5 внутри категории: среднее, минимум, максимум; при пустом множестве — **«—»**; иначе округление как в §4.3.

### 4.7. Диаграмма одно- / многоэтапных маршрутов (не в таблице)

Для каждого **`id_appointment`** в выборке **C** — число строк `List_item` этого приёма в периоде.

Учёт в doughnut за период:

| C | Сегмент |
|---|---------|
| 1 | Одноэтапные маршруты |
| ≥ 2 | Многоэтапные маршруты |
| 0 | не учитывается (в выборке по этапам отсутствует) |

Агрегат по всем категориям: `ForMultiStageRoutesMix`.

---

## 5. Границы периода

**`fromDo` ≤ `date_arrival` ≤ `toDo`** (`CatalogReportShared.ParsePeriod`).

---

## 6. Содержание отчёта (что видит пользователь)

**Таблица: 8 колонок.**

1. **Категория** — `Category.name`.
2. **Приёмов** — §4.1.
3. **Среднее ожидание до вызова, мин** — §4.3.
4. **Минимальное ожидание до вызова, мин** — §4.4.
5. **Максимальное ожидание до вызова, мин** — §4.4.
6. **Средняя длительность приёма, мин** — §4.6.
7. **Минимальная длительность приёма, мин** — §4.6.
8. **Максимальная длительность приёма, мин** — §4.6.

Итоговой строки по всем категориям **нет** — каждая строка уже агрегирует период по своей категории.

**Предпросмотр (JSON):** doughnut «Одноэтапные / Многоэтапные маршруты» по итогам периода (§4.7); при превышении лимита строк таблицы — усечение и подсказка о полном отчёте в файле.

Имя файла экспорта: `service-categories-comparison.csv`. HTML/PDF — с диаграммой при наличии `PreviewCharts`.

---

## 7. Параметры UI / API

Только период (`dateFrom` / `dateTo`). Дополнительных `CustomParams` нет.

---

## 8. Связь с названием в конфигурации

В `appsettings.json` для этого отчёта указано краткое описание; данный документ **уточняет и заменяет** его для целей разработки и приёмки.
