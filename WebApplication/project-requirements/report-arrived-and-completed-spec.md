# Отчёт «Поступило и завершено» (`arrived-and-completed`): содержание и правила расчёта за период

Документ задаёт **единые определения и ожидаемое содержание** отчёта, чтобы результат за выбранный период был **интерпретируемым** и пригодным для сопоставления **запланированного потока** (`Appointment`) с **фактическими этапами маршрута** (`List_item`) и выявления **неявок на приём** (план без факта) и **незавершённого фактического обслуживания** (есть этапы, маршрут не доведён по времени). Идентификатор в каталоге отчётов — `arrived-and-completed` (см. `appsettings.json` → `Reports.Catalog`).

---

## 1. Назначение

Отчёт отвечает на вопросы:

- Сколько **зарегистрированных приёмов** (`Appointment`) приходится на каждый календарный день и категорию за период?
- Сколько из них — **неявки на приём** (нет ни одной строки `List_item`)?
- Сколько приёмов имеют **полностью завершённый фактический маршрут** (по всем строкам `List_item` задано окончание обслуживания)?
- Сколько приёмов имеют **незавершённое фактическое обслуживание** (есть хотя бы один этап без окончания по времени)?

Классификация этапов по полям времени (§4.4–4.6) **не выводится отдельными столбцами** таблицы, но используется в определениях §4.7–4.8.

Пользователь задаёт **период** как пару **дата и время** «с» / «по»; в отбор приёмов входит **`DateArrival`** как календарный день в полуинтервале дат, полученном из запроса (см. §5). Время прибытия `TimeArrival` для **включения приёма в день** не используется: день потока = календарная **дата прибытия** приёма.

---

## 2. Объект анализа и разрезы

- **Строка отчёта** — пара **(день прибытия, категория)**:
  - **день прибытия** — значение `Appointment.date_arrival`;
  - **категория** — `Appointment.id_category` с подписью из справочника `Category.name`, порядок категорий внутри дня — по `Category.priority` по возрастанию, затем по `Category.name`.
- **Запланированный приём** — одна запись `Appointment` (`id_appointment`); одна дата прибытия и одна категория; **фактический маршрут** — множество строк `List_item` с тем же `id_appointment` (если есть).
- **Этап маршрута** — одна строка `List_item`; показатели по этапам считаются по **всем** этапам приёмов строки (день × категория). Классификация этапов по §4.4–4.6 опирается **только на поля времени** (`time_call`, `time_start_servicing`, `time_end_servicing`), **а не** на имя статуса (`Status_item_list.name`). Имя статуса с подстрокой «неяв» **не** трактуется в этом отчёте как отдельная категория «неявка на приём».

---

## 3. Источники данных (внешняя БД электронной очереди)

| Сущность | Таблица | Назначение в отчёте |
|----------|---------|----------------------|
| Приём | `Appointment` | День `date_arrival`, категория `id_category`; множество запланированных приёмов в строке. |
| Этап | `List_item` | Вызов `time_call`, начало/окончание `time_start_servicing` / `time_end_servicing`. |
| Категория | `Category` | Наименование, `priority` для сортировки. |

Справочник `Status_item_list` в формулах §4.4–4.6 **не** используется. Справочник `Specialty` в базовой таблице отчёта **не** используется.

---

## 4. Определения

### 4.1. Число запланированных приёмов (в строке)

Число **уникальных** `id_appointment` в строке (день *D*, категория *C*), для которых одновременно: `date_arrival` = *D*, `id_category` = *C*, *D* в диапазоне по §5.

### 4.2. Неявка на приём

**Неявка на приём** — запланированный приём из строки, для которого **нет ни одной** строки `List_item` с данным `id_appointment` среди этапов, загруженных для приёмов этой строки (все этапы приёмов группы день × категория).

### 4.3. Число записей этапа в List_item (всего)

Число строк `List_item`, относящихся к приёмам этой строки.

### 4.4. Завершённый этап по данным времени

Этап считается **завершённым**, если одновременно заданы **`time_call`** и **`time_end_servicing`**. Поле **`time_start_servicing`** для признания завершения **не обязательно** (см. качество данных §7).

### 4.5. Этап без вызова и без окончания обслуживания

Этап попадает в этот счётчик, если **`time_call`** и **`time_end_servicing`** **не** заданы.

### 4.6. Этап с вызовом или началом обслуживания без окончания

Этап попадает в этот счётчик, если **`time_end_servicing`** **не** задан и задан **`time_call`** **или** **`time_start_servicing`**. Этапы только из §4.5 сюда **не** входят.

### 4.7. Число приёмов с незавершённым фактическим обслуживанием

Число уникальных `id_appointment` в строке, для которых: существует **хотя бы одна** строка `List_item` и **хотя бы у одной** строки `List_item` этого приёма **не** задан `time_end_servicing`. Приёмы **без** ни одного `List_item` сюда **не** входят (они учитываются в §4.2).

### 4.8. Число приёмов с полностью завершённым фактическим маршрутом

Число уникальных `id_appointment` в строке, для которых: есть **хотя бы одна** строка `List_item` и **у каждой** строки `List_item` этого приёма задан **`time_end_servicing`**. Если у приёма **нет** ни одного `List_item`, приём **не** входит в этот счётчик.

### 4.9. Согласованность типов приёма в строке

Для каждого запланированного приёма в строке ровно одно из: неявка на приём (§4.2); полностью завершённый фактический маршрут (§4.8); незавершённое фактическое обслуживание (§4.7).

---

## 5. Границы периода

- Из запроса генерации (`DateFrom`, `DateTo`, инвариантная культура) строятся моменты периода; **даты отчёта** — `DateOnly` от этих моментов: `fromDo`, `toDo` (как в `CatalogReportShared.ParsePeriod`).
- Приём попадает в отчёт, если **`date_arrival`** удовлетворяет **`fromDo` ≤ `date_arrival` ≤ `toDo`** (включительно по календарной дате).
- Время суток в `DateFrom`/`DateTo` **не** сужает включение приёма по дню.

---

## 6. Содержание отчёта (что видит пользователь)

Границы отчётного периода отображаются в UI в подзаголовке модалки; в теле таблицы **не** дублируются отдельной строкой.

**Таблица: 6 колонок.** Порядок строк: по возрастанию **даты**, внутри даты — по **`Category.priority`**, затем **`Category.name`**.

**Группировка по дате (визуальное представление):** для подряд идущих строк детализации с **одинаковой** календарной датой прибытия во **второй и последующих** строках группы в колонке 1 (**«Дата»**) выводится **пустая** ячейка; в **HTML-, PDF-экспорте и предпросмотре** первая колонка оформляется с **`rowspan`**. В **CSV** пустые ячейки даты заменяются переносом предыдущей даты группы (как у отчёта «Загрузка и простои»; перенос только для строк, похожих на детализацию, см. код экспортёра).

1. **Дата** — `date_arrival`, `yyyy-MM-dd`, или пусто при группировке.
2. **Категория** — `Category.name`.
3. **Зарегистрированных приёмов** — §4.1 (число запланированных приёмов в строке).
4. **Неявок на приёмы** — §4.2.
5. **Приёмов с завершённым маршрутом** — §4.8.
6. **Приёмов с незавершённым обслуживанием** — §4.7.

**Строка «Итого за период»** (полный экспорт): в колонках 1–2 как сейчас; в колонках **3–6** — **суммы** по строкам детализации.

**Предпросмотр (JSON):** при превышении лимита — усечение, строка-подсказка, **«Итого (по полным данным)»** с суммами по полным данным периода. **Диаграмма** (doughnut): суммы по колонкам **4–6** за период (полные данные, не из усечённой таблицы); нулевые сегменты не включаются; подписи сегментов как в `ReportPreviewChartDescriptors.ForArrivedCompletedAppointmentMix`; экспорт HTML/PDF — как у других отчётов с `PreviewCharts`.

Название отчёта обобщает **поступивший** поток приёмов за период; **завершённый маршрут** — один из исходов (колонка 5), на диаграмме он сопоставим с неявками и незавершённым обслуживанием.

При отсутствии приёмов в периоде — **пустая** таблица.

Имя файла экспорта: `arrived-and-completed.csv`.

---

## 7. Качество данных и пустые поля

- Завершённый этап при пустом `time_start_servicing` допустим (см. §4.4).
- Приём **без** `List_item`: колонка 3; колонка 4; колонки 5–6 = 0.

---

## 8. Согласованность показателей

- Колонка **5** ≤ колонка **3** − колонка **4**; колонка **6** ≤ колонка **3** − колонка **4**.
- Для каждого запланированного приёма в строке ровно одно из: неявка (§4.2); полностью завершённый маршрут (§4.8); незавершённое обслуживание (§4.7) — см. §4.9; следовательно **колонка 5 + колонка 6 = колонка 3 − колонка 4**.

---

## 9. Связь с названием в конфигурации

В `appsettings.json` для этого отчёта указано краткое описание; данный документ **уточняет и заменяет** его для целей разработки и приёмки: фактическое содержание отчёта и формулы должны соответствовать **этому файлу**.
