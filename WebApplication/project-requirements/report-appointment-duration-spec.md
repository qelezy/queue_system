# Отчёт «Длительность приёма» (`appointment-duration`): содержание и правила расчёта за период

Документ задаёт **единые определения и ожидаемое содержание** отчёта для приёмки и интерпретации результатов. Идентификатор в каталоге — `appointment-duration` (см. `appsettings.json` → `Reports.Catalog`). Реализация: `AppointmentDurationReportGenerator`, сборка таблицы — `AppointmentDurationReportBuilder`.

---

## 1. Назначение

Отчёт отвечает на вопросы:

- Сколько **завершённых по времени этапов обслуживания** было за период в выбранном **срезе** (врач, специальность этапа или кабинет), **по календарным дням**?
- Каковы **типичная** и **максимальная** **длительность приёма** на этапе (в минутах) и **отклонение от норматива** `Specialty.time_servicing`?

Справочник статусов этапа **не** используется.

---

## 2. Объект анализа и разрезы

- **Базовая единица наблюдения** — одна строка **`List_item`**, для которой одновременно:
  - талон `Appointment` попадает в период по §5;
  - заданы **`time_start_servicing`** и **`time_end_servicing`**.
- **Длительность приёма на этапе** (минуты):

  \[
  \text{Combine}(\text{date\_arrival}, \text{time\_end\_servicing}) - \text{Combine}(\text{date\_arrival}, \text{time\_start\_servicing})
  \]

  (`EqDateTimeExtensions.CombineOnArrivalDate`).

- **Строка детализации** — одно значение выбранного среза **внутри календарного дня** `Appointment.date_arrival`:
  - **`doctor`** (по умолчанию) — `Doctor.full_name` (`List_item.id_doctor`);
  - **`specialty`** — `Specialty.definition` (`List_item.id_specialty`);
  - **`cabinet`** — подпись кабинета `Каб. {CabinetNumber}` (`List_item.id_cabinet`).
- Параметр UI / запроса: `CustomParams.analysisMode` = `doctor` | `specialty` | `cabinet`.
- В режиме **`doctor`** дополнительно колонка **«Специализация врача»** — уникальные `Specialty.definition` этапов строки (врач × день; через «; »), как в «Загрузка и простои». Кабинет в этой таблице **не** выводится.
- **Норматив** на этап — `Specialty.time_servicing` (мин) для `List_item.id_specialty`.
- **Важно:** у многоэтапного талона несколько строк `List_item` дают **несколько** независимых длительностей. Поле `service_time` в этом отчёте **не** используется.

---

## 3. Источники данных (внешняя БД электронной очереди)

| Сущность | Таблица | Назначение в отчёте |
|----------|---------|----------------------|
| Этап | `List_item` | `time_start_servicing`, `time_end_servicing`, врач, специальность, кабинет. |
| Приём | `Appointment` | `date_arrival` для склейки даты и времени и группировки по дню. |
| Врач | `Doctor` | ФИО (срез `doctor`). |
| Специальность | `Specialty` | `definition` (срез `specialty` и колонка этапа в режиме `doctor`); `time_servicing` — норматив. |
| Кабинет | `Cabinet` | `cabinet_number` (срез `cabinet`). |

---

## 4. Определения

### 4.1. Включение единицы наблюдения

Строка учитывается, если длительность в минутах удовлетворяет **0 ≤ длительность < 10080**.

### 4.2. Показатели по строке детализации / итогам

После фильтра §4.1:

- **Завершённых приёмов** — число **уникальных** талонов (`Appointment.id_appointment`) среди учтённых этапов ячейки (один талон с несколькими этапами — один раз).
- **Средняя длительность, мин** — среднее фактических минут по этапам ячейки, **F1**.
- **Норматив, мин** — среднее `time_servicing` по этапам ячейки, **F1**.
- **Отклонение, мин** — средняя длительность − норматив; при нуле этапов — **«—»**.
- **Минимум, мин** — минимум фактических минут, **F1**.
- **Максимум, мин** — максимум фактических минут, **F1**.

Блок **Итого по врачам / специальностям / кабинетам** (в конце таблицы): по одной строке на каждое значение среза за период; «Завершённых приёмов» — уникальные талоны по этапам строки; средняя длительность и норматив — по **всем** минутам этапов агрегата; мин./макс. — по этапам; отклонение — из средних длительности и норматива. Блока **«Итого за день»** в этом отчёте **нет** (в отличие от «Загрузка и простои»).

Пустая подпись среза в таблице — **«—»**.

### 4.3. Порядок строк

- Дни — по возрастанию `date_arrival`.
- Внутри дня — строки среза по **возрастанию** подписи среза (ФИО / специальность / кабинет).

### 4.4. Оформление итогов

В конце таблицы — **«Итого по врачам»** / **«Итого по специальностям»** / **«Итого по кабинетам»** (`totals-start`) и по одной строке итога на срез за период (`period-total`). При усечении предпросмотра — полный блок периодных итогов по всем срезам.

---

## 5. Границы периода

- `CatalogReportShared.ParsePeriod` — см. отчёт «Ожидание до приёма» §5.
- Отбор талонов: **`fromDo` ≤ `date_arrival` ≤ `toDo`** по календарной дате; время в `DateFrom`/`DateTo` день не сужает.

---

## 6. Содержание отчёта (что видит пользователь)

Границы периода — в подзаголовке модалки; в таблице **не** дублируются.

**Таблица: 8 или 9 колонок** (режим `doctor` — с колонкой «Специализация врача»).

| # | Колонка | Режим |
|---|---------|--------|
| 1 | Дата | всегда; пусто во 2+ строках группы дня |
| 2 | Врач / Специальность / Кабинет | по `analysisMode` |
| 3 | Специализация врача | только `doctor` |
| 4 | Завершённых приёмов | distinct `id_appointment` |
| 5 | Средняя длительность, мин | §4.2 |
| 6 | Норматив, мин | §4.2 |
| 7 | Отклонение, мин | §4.2 |
| 8 | Минимум, мин | §4.2 |
| 9 | Максимум, мин | §4.2 |

После детализации по дням — в конце таблицы **Итого по врачам** (или по специальностям / кабинетам) с одной строкой на срез за период.

**Диаграмма (`groupedBar`):** ось X — дни (`dd-MM-yyyy`); **топ-8** столбцов среза на день; в **одном столбце** среза — наложение: широкий светлый (норматив `time_servicing`) и уже насыщенный (средняя фактическая длительность, мин) за пару (день, серия). При отсутствии этапов — 0. Данные — из **полной** выборки, не из усечённых строк таблицы.

**Предпросмотр (JSON):** при `Rows.Count > 500` — усечение детализации, `PreviewRowsTotal` / `PreviewRowLimit`, хвост — подсказка и **полный** блок периодных итогов по всем срезам; тост на клиенте.

**CSV:** дата в первом столбце переносится в пустые ячейки группы дня (как у waiting).

Экспорт: **csv**, **xlsx**, **html**, **pdf** — полная таблица и диаграмма (`ReportTabularExporter`). PDF — **портретная** ориентация. Имя файла: `appointment-duration.csv` (базовое имя без расширения).

Mock без БД: `GenerateAppointmentDurationOffline`.

---

## 7. Качество данных

Этапы с неполной парой начала/окончания обслуживания в отчёт **не** входят.

---

## 8. Связь с названием в конфигурации

В `appsettings.json` для этого отчёта указано краткое описание (детализация по врачу, специальности и кабинету); фактическое содержание и срезы задаёт **этот документ** для разработки и приёмки.
